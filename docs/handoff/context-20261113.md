## 완료된 변화와 실제 증거

- alpha.9 `qa-reusable-document-authoring`: 재사용 template/catalog/create 및 순수 compose API/CLI, 원본 namespace/sourceMap/결정성, Dart 원본 차등·독립 패키지 인수 완료. 실행 schema를 Checker에서 새로 만들지 않는다.
- alpha.10 `qa-event-settlement-delivery`: 이미 취소된 signal 때문에 건강한 실패 정리 callback이 ENGINE_ERROR로 오인되던 경로 수정. 실패 정리/terminal은 각각 최대 1초 예산을 사용한다. 실제 observer 오류와 CLEANUP_ERROR·Agent unknown/quarantine은 유지한다.
- Engine `npm run verify` 206/206 PASS. 독립 설치 167파일/source SHA 대조 및 API/CLI 실제 Chromium PASS·의도 FAIL·cancel, callback/JSONL terminal 인수. 최초 외부 timeout harness의 속도 가정 실패와 결정적 waitFor fixture 수정 뒤 같은 tgz 재검증을 [alpha.10 검증](../validation-alpha.10.md)에 구분했다.
- Checker 실제 alpha.10 HTTP/Chromium/Agent 인수: Run 7개(PASS 5·의도 FAIL 1·취소 1), PNG 6개, lease 4개 ACK/resource 해제/owner retired. durable result/events와 서버 저장본 7/7 정확 일치. 정상 취소 cleanupErrors는 빈 배열이고 run.finished를 수신했다.
- Checker 전체 verify exit 0(server 56/56·TS 12/12), SDK 339파일 불변. 마지막 demo 설정/문서 편집은 후속 syntax·focused·foundation·lint·strict로 검증했다. 관리자 SQLite·배포 1904파일 인수와 Engine 담당의 읽기 검토는 [후속 리뷰](../architecture/alpha10-server-runtime-review.md)에 구분했다.

현재 실제 source/contract pin은 고정 아카이브와 확인하되 각 저장소에서 문서 수정 시점까지 모든 테스트를 다시 돌렸다고 표현하지 않는다. 과거 alpha.6/8/9 검증 기록도 해당 시점의 역사 증거다.

## Checker 연결 지점

Checker 저장소 기준 주요 경로:

- `packages/contract/runtime/engine-runtime.json`: 새 서버 canonical alpha.10 pin. `apps/server/scripts/prepare-server-runtime.mjs`가 `.local/engine-server-alpha10`에 별도 설치하며 기존 alpha.6 설치는 보존한다.
- `apps/server/scripts/server-runtime.mjs`: CLI/manifest paired override와 demo startup 이전 구 Agent 등록 readOnly guard. 운영 bootstrap과 사용자 설정의 자동 migration은 아니다.
- `apps/app/engine-runtime-pin.json`, `scripts/install-desktop-engine.mjs`, `scripts/lib/authoring-artifact.mjs`: Desktop exact pin/설치 receipt/작성 metadata 소비. 실제 배포 위치는 Checker의 현재 문서를 확인한다.
- `apps/server/scripts/verify-runtime-integration.mjs`, `artifacts/runtime-alpha10/acceptance.json`, `artifacts/runtime-alpha10/run-unCN6f/{verification,durable-evidence-comparison}.json`: 실제 서버 인수 원본. artifacts는 Git 제외 자료다.
- `docs/server-runtime-alpha10.md`, `docs/validation-server-runtime-alpha10.md`, `openspec/changes/qa-server-agent-alpha10-runtime`: 서버 실행 절차와 완료 범위. 앱 Release와 다른 PC readiness는 Checker 담당 기록을 별도로 따른다.

신규 Run은 현재 runtime exact match를 요구한다. 구 Run GET은 원래 version/identity로 조회하며 저장된 결과를 새 runtime으로 소급 수정하지 않는다. 구 Agent 등록·lease·Suite pin도 자동 승격하지 않는다. 새 identity/state로 검증하며 active/unknown 장치의 재배정은 기존 보수적 정책을 유지한다.

## 미완료와 재개 순서

1. Git root/HEAD/dirty/upstream을 확인하고 이 문서 및 각 AGENTS.md를 읽는다. 고정 archive/hash, 완료 명세, 현재 Checker pin과 이전 역사 pin을 구분한다.
2. `qa-web-locator-candidates` proposal/design/spec/tasks는 작성·strict PASS이며 설계 검토 승인을 받았다. **제품 apply는 아직 보류, 6 tasks 모두 미완료**다. alpha.10 통합 완료가 자동 apply 승인을 뜻하지 않는다. 다음 관리 지시를 확인한다.
3. locator 첫 단위는 명시 seed에서 data-testid/id 후보 최대 2개를 관측하여 현재 고유성/동일성을 확인하는 별도 web-tools API/CLI 설계다. 새 브라우저 navigation은 script/network 부작용이 있다. recorder/GUI picker/행동 recording 완성이 아니며 alpha.11은 제안 버전이다.
4. Android/iOS Appium protocol 구현과 실패/취소 회귀는 있으나 실제 장치 인수는 미완료다. TV·whitebox·완전한 recorder는 별도 설계가 필요하다. 다른 물리 PC·외부 production·실제 Slack 인수도 로컬 테스트와 구분한다.
5. OpenSpec sync/archive 행정은 후속 변경과 미검증 실기기 조건을 대조한 뒤 수행한다. 열린 change가 있다는 이유로 구현을 모두 미완료로 보거나, 테스트 미완료를 archive로 숨기지 않는다.
